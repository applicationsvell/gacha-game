# 試作: ロジックと自動テスト

企画提案書(`../docs/PROPOSAL.md`)の、ガチャ・経済・戦闘のロジックです。画面はまだありません。

## 動かし方

Node.js 22.18 以上が必要です(TypeScript をそのまま実行します)。

```
npm install      # 型チェック用の TypeScript だけ入る
npm test         # 自動テスト
npm run check    # 型チェックとテスト
```

## 構成

| ファイル | 内容 | 提案書 |
|---|---|---|
| `src/core/rng.ts` | シード付き乱数。同じシードなら同じ結果 | — |
| `src/core/types.ts` | レア度、仕上げ、種族、能力の型 | 4.2、6.1節 |
| `src/core/cards.ts` | セットの組み立て、★の倍率、能力の説明文 | 6.1節 |
| `src/core/gacha.ts` | パック開封、天井、ゴッドパック、仕上げ、最初の5パックの保証、表示用の排出率 | 4.2〜4.4節 |
| `src/core/collection.ts` | 手持ち、★の強化、交換ポイント、図鑑 | 4.3、4.6節 |
| `src/core/capsule.ts` | カプセルマシン(中身が減っていく抽選) | 4.1節 |
| `src/core/battle.ts` | 編成バトル。乱数を使わず、同じ編成なら同じ結果 | 6.1節 |
| `src/core/economy.ts` | 買取価格、相場とブーム、客の購入と値切り | 5.2、7章 |
| `src/data/set1.ts` | 第1セット60種、レリック7種、カプセル1台 | 4.2節 |

ゲームの状態を持つ関数(`openPack` など)は、渡された状態を書き換えます。

## テストで確かめていること

- 排出率が `tools/gacha_sim.py` のシミュレーションと一致する(SR以上33.9%、SSR以上8.36%、還元率約59%など)
- SSR以上は30パック以内、URは200パック以内に必ず出る
- 最初の5パックで SSR 以上が必ず出る
- 交換ポイントを併用すると、約110パックで全60種がそろう
- カプセルは最後まで引けば中身が全部出て、目玉までは平均約25.5回
- 戦闘の各能力(分身、盾、回復、道連れ、封印竜の★2化、商才)が仕様どおりに働き、全カードの組み合わせで必ず終わる
- 相場が上下限の中で動き、客が好みと予算に応じて買う、値切る、見送る

わざと不具合を入れて(天井を外す、盾を無視するなど)、テストが落ちることも確かめています。

## 仮置きの部分

カードの能力と数値、客の予算、相場の揺れ幅は、試作用の仮の値です。プレイテストで調整します。
